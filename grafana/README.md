# Grafana Dashboard Management

## Goal
Prevent unintentional regression (dashboards reverting to minimal structure) and ensure reproducible, versioned observability.

## Structure
- `.grafana/provisioning_baseline/dashboards_src/` -> Stable dashboards (provisioned, read-only in UI).
- `scripts/grafana/dashboard_guard.py` -> Hash / panel count guard.
- `grafana/dashboard_hashes.json` -> Baseline hashes (generated by guard script).

## Workflow
1. Modify dashboard JSON directly in repo (no UI edits).
2. Run guard scan to refresh baseline if change is intentional:
   ```bash
   python scripts/grafana/dashboard_guard.py --scan --out grafana/dashboard_hashes.json
   ```
3. Commit both the dashboard JSON and updated `dashboard_hashes.json`.
4. CI / local pre-commit can run:
   ```bash
   python scripts/grafana/dashboard_guard.py --check --baseline grafana/dashboard_hashes.json
   ```
   to detect accidental regressions (panel drops, minimal resets).

## Provisioning Settings
`dashboards.yml` sets `disableDeletion: true` and `editable: false` for stability. To make a dashboard editable, move it to a different provider or change settings deliberately.

## Adding a New Dashboard
1. Create JSON in `dashboards_src`.
2. Run scan.
3. Commit.

## Regeneration / Removal
If a dashboard is intentionally reduced (panel removal), run scan and include rationale in commit message `BREAKING: reduced panels for <reason>`.

## Common Pitfalls
- Duplicated `uid` values across files -> first loaded may override expected layout.
- Leaving old minimal JSON with same title -> confusion; delete obsolete files.
- Forgetting to update baseline after intentional expansion -> check will fail.

## Future Enhancements
- UID duplicate checker script.
- Nightly export & diff against repo to detect drift.
- Generated dashboards subfolder (if spec generation revived) kept isolated.

## Quick Commands
```bash
python scripts/grafana/dashboard_guard.py --scan
python scripts/grafana/dashboard_guard.py --check
```

## Hash File
Do not hand-edit `grafana/dashboard_hashes.json`; always regenerate via scan.
